# 数据预处理门控清单

本文件用于约束数据处理阶段。AI 不能默认清洗数据，必须先判断是否需要预处理，并说明每个处理动作的依据、备选方案和对建模的影响。

## 1. 是否需要预处理

AI 应先检查并回答：

- 是否存在缺失值。
- 是否存在异常值。
- 是否存在重复记录。
- 是否存在数据类型错误。
- 是否存在单位或量纲不一致。
- 是否存在类别不平衡。
- 是否存在时序、空间或网络结构不规整。
- 是否存在编码、路径或格式读取问题。

如果判断“不需要预处理”，必须说明原因；如果需要预处理，必须说明每一项处理对后续模型的影响。

## 2. 预处理方案选择

每个预处理动作都应给出：

| 项目 | 要求 |
|---|---|
| 问题类型 | 缺失、异常、重复、类型、单位、编码、样本不平衡等 |
| 推荐方法 | AI 推荐的主要方法 |
| 备选方法 | 至少 1-2 个可选方案 |
| 适用场景 | 说明为什么适合当前赛题 |
| 风险 | 可能引入的偏差或信息损失 |
| 用户确认 | 处理前应等待用户确认 |

常见选择：

- 缺失值：删除、均值/中位数/众数填补、插值、KNN 填补、模型填补。
- 异常值：IQR、Z-score、箱线图、业务规则、保留但标记。
- 类型转换：数值转换、日期解析、类别编码。
- 标准化：Min-Max、Z-score、RobustScaler。
- 类别变量：One-Hot、Label Encoding、目标编码。
- 时序数据：重采样、插值、滚动窗口、季节性处理。

## 3. 预处理前后对比

预处理完成后，必须输出：

- 原始数据维度。
- 处理后数据维度。
- 缺失值变化。
- 异常值处理数量。
- 删除或填补的字段/行。
- 关键字段类型变化。
- 处理前后关键统计量对比。
- 是否可能影响模型结论。

建议写入：

- `docs/03_data_report.md`
- `data/metadata/data_profile.json`

## 4. 代码要求

确认预处理方案后，代码应：

- 使用相对路径读取 `data/raw/` 或 `data/external/`。
- 输出到 `data/processed/`。
- 保留原始数据不修改。
- 包含清晰异常提示，例如路径错误、编码错误、格式错误。
- 输出中间统计结果。
- 必要时生成预处理前后对比图。

## 5. 论文落地

论文中数据预处理部分至少说明：

- 数据来源。
- 字段含义和单位。
- 为什么需要预处理。
- 采用了什么方法。
- 处理前后有什么变化。
- 这些处理对模型可靠性的影响。
