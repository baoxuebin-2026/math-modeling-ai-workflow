# 逐问图表规划门控

本文件用于在写可视化代码之前，先确定每一问需要哪些图、为什么需要这些图、图在论文中支撑什么结论。图表规划必须先于 `code/q*/visualize_q*.py` 实现，避免先画一堆图再勉强塞进论文。

## 核心原则

论文图表不是装饰，而是证据链的一部分。每张图必须回答一个明确问题：

- 它证明了什么结论？
- 它比表格或文字更有说服力在哪里？
- 它的数据来自哪里？
- 它放在论文哪一节？
- 它是否值得进入正文，还是只适合放入附录或删除？

## 强制流程

每一问进入可视化代码实现前，AI 必须先输出“逐问图表证据链表”，等待用户确认。确认后才能写或修改 `code/q*/visualize_q*.py`。

推荐表格格式：

| 问题 | 论文要证明的结论 | 必画图 | 可选图 | 数据来源 | 论文放置位置 | 不画什么 | 采用理由 |
|---|---|---|---|---|---|---|---|
| Q1 | 例如：校准有效、误差降低 | 目标函数曲线、前后对比图 | 局部放大图 | `docs/results/q1_results.json` | 问题一结果分析 | 无信息量折线图 | 能直观看到最优点和改进幅度 |

## 图表分层

一篇完整论文的图表通常按以下层次组织：

| 层次 | 作用 | 常见图型 |
|---|---|---|
| 框架图 | 说明整体建模路线和模块关系 | 总体流程图、模型框架图 |
| 数据图 | 说明数据结构、异常、缺失、分布特征 | 分布图、箱线图、相关性热力图、空间分布图 |
| 模型图 | 说明参数估计、优化过程或模型机制 | 目标函数曲线、收敛曲线、模型结构图 |
| 结果图 | 展示核心计算结果 | 对比图、轨迹图、排序图、方案图 |
| 验证图 | 证明结果可信 | 残差图、误差分布、置信区间、交叉验证图 |
| 敏感性图 | 证明结果稳定或解释参数选择 | 参数扫描图、鲁棒性分析图、情景对比图 |

## 常见题型图表建议

| 题型 | 必优先考虑的图 | 说明 |
|---|---|---|
| 数据预处理/数据理解 | 数据分布图、缺失异常统计图、变量相关性热力图 | 证明数据处理有必要，而不是大规模机械清洗 |
| 参数估计/校准 | 目标函数曲线、估计前后对比图、残差分布图 | 证明参数不是拍脑袋，校准后确实改善 |
| 预测/拟合 | 真实-预测对比图、残差图、误差分布图、交叉验证图 | 同时展示精度和误差结构 |
| 分类/识别 | 混淆矩阵、ROC/PR 曲线、特征重要性图 | 说明识别效果、错分类型和关键因素 |
| 优化/调度 | 方案示意图、甘特图、约束裕度图、敏感性分析图 | 证明方案可执行、约束满足、结果不是普通贪心 |
| 综合评价 | 指标权重图、排名稳定性图、热力图、雷达图 | 说明评价体系、权重贡献和排序稳定性 |
| 机理/仿真 | 参数响应曲线、情景对比图、敏感性分析图 | 展示机制、趋势和关键参数影响 |
| 空间路径/网络 | 路径态势图、节点-边关系图、热力图、流量图 | 展示空间结构、任务点关系和方案覆盖 |

## 选择正文图的标准

正文图应满足至少一个条件：

- 支撑摘要或结论中的关键数值。
- 支撑模型选择、参数选择或优化方案。
- 展示表格难以表达的空间、时间、分布或结构关系。
- 能提前回应评委可能质疑的问题。

以下图通常不进入正文：

- 与论文结论无直接关系的探索图。
- 只有 0、100%、单点或空数据的图。
- 信息量和表格重复，且没有额外解释力的图。
- 只是为了“看起来丰富”的装饰图。

## 与其他门控的关系

- 本文件解决“该画什么图”的问题。
- `docs/workflow/05_visualization_rules.md` 解决“可视化代码怎么组织、图怎么命名”的问题。
- `paper/workflow/figure_quality_gate.md` 解决“生成后的图片是否达到论文质量”的问题。

三者顺序必须是：

```text
先规划图表证据链 → 再写 Python 可视化代码 → 生成图片后逐张查看和修正
```
