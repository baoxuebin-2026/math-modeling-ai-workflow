# 模型决策门控

## 核心要求

先说明数学任务和题目困难，再选择模型。算法名不构成创新。

每一问至少明确：输入、输出、变量、单位、目标、约束、边界、与上一问的接口、官方交付物、验证等级和预期结果 schema。

## 路线比较

- 默认保留一个可解释基线。
- 只有当基线存在可证明缺陷时才增加改进模型。
- 若一种路线因题意、数据或时间限制明显占优，可说明理由后免除机械双方案和打分表。
- 创新必须指出真实痛点、改变的数学部件、基线差异、验证方法和论文证据位置。

## 模型总括

关键目标和约束先逐式解释，再用一个紧凑总括式集中呈现：目标函数、决策变量、分组约束和参数边界。默认采用 `aligned`，不强制跨越整个模型的巨大左大括号。

## 确认边界

只有主模型路线、重要假设、会改变题意的口径和结果评价标准需要用户硬确认。局部记号、等价变形和可逆实现细节不重复确认。
