# 模型决策门控清单

本文件用于约束模型选择阶段。AI 不能直接指定唯一模型，必须先给出基础方案、创新方案、推荐理由和风险，等待用户确认后再进入代码实现。

## 1. 题目与任务定位

每一问先判断任务类型：

- 机理建模
- 预测建模
- 评价排序
- 优化决策
- 分类判别
- 聚类分群
- 网络建模
- 仿真模拟
- 参数反演
- 政策/社会科学分析

AI 必须说明判断依据，不能只给标签。

## 2. 直接目标与隐含目标

每一问应明确：

| 项目 | 说明 |
|---|---|
| 直接目标 | 题目表面要求输出什么 |
| 隐含目标 | 该问为后续问题提供什么支撑 |
| 输入 | 数据、参数、约束或前一问结果 |
| 输出 | 数值、排名、方案、图表、判断或建议 |
| 评价指标 | 如何判断模型做得好 |

## 3. 双方案模型推荐

每一问至少给出两个方案：

| 方案 | 定位 | 要求 |
|---|---|---|
| 基础保分模型 | 稳妥、可解释、易实现 | 必须贴合题意，作为基线 |
| 创新提升模型 | 改进、融合、场景化 | 必须说明真实价值，不能为创新而创新 |

每个方案都要说明：

- 核心原理。
- 为什么适合本题。
- 需要哪些数据。
- 变量和参数如何定义。
- 优点。
- 局限性。
- 实现难度。
- 可解释性。
- 验证方式。

## 4. 推荐模型评分卡

推荐主模型前，应按 1-10 分打分：

| 维度 | 权重 | 说明 |
|---|---:|---|
| 适配性 | 35% | 是否匹配题目目标、数据和约束 |
| 可解释性 | 25% | 是否容易写进论文、说服评委 |
| 创新性 | 15% | 是否有合理改进或组合 |
| 可实现性 | 15% | 是否能在比赛时间内完成并复现 |
| 鲁棒性 | 10% | 是否能经受噪声、参数变化和边界情景 |

综合得分不应替代用户判断，但必须作为推荐依据。

## 5. 用户确认点

进入代码实现前，用户至少确认：

- 每问任务类型是否正确。
- 是否采用 AI 推荐主模型。
- 是否保留基础模型作为对照。
- 创新点放在哪一问。
- 是否接受模型复杂度。
- 结果需要以什么口径呈现。

确认结果应写入：

- `docs/decision_log.md`
- `docs/02_model_plan.md`

## 6. 论文落地

模型路线最终要能支持论文中的：

- 问题分析。
- 模型假设。
- 符号说明。
- 模型建立。
- 求解步骤。
- 结果分析。
- 模型检验。
- 优缺点评价。
