# 单章节生成与验收门控清单

本文件用于约束 AI 每次只生成一个论文章节，并在进入下一章前完成本章核对。

## 生成前必须说明

AI 在写本章前必须先给出：

- 本章文件名。
- 本章对应论文位置。
- 本章需要读取的建模素材。
- 本章预计引用的公式、图表、表格、结果文件和代码文件。
- 本章不应该写入的内容，避免提前泄露后文结果或重复其他章节。

## 生成后必须核对

每个章节写完后，AI 必须检查：

- 是否只写了当前章节，没有顺手生成后续章节。
- 是否所有结论都有 `docs/`、`figures/`、`code/` 或 `docs/results/` 的来源。
- 是否没有凭空编造数据、指标、图号、表号和参考文献。
- 是否术语、模型名、变量名与已确认材料一致。
- 是否与前面已确认章节重复。
- 是否存在“效果良好”“显著提升”等没有数值支撑的表达。
- 是否有需要用户选择的地方，并明确列出。

如果当前章节是某一问的模型建立与求解章节，还必须检查：

- 是否写清楚“问题难点 → 数据/业务观察 → 基线模型 → 改进模型 → 求解方法 → 结果 → 对比/检验 → 小结”的证据链。
- 是否说明后一问如何继承或改进前一问。
- 是否解释结果差异，而不是只罗列结果。
- 是否把复杂模型的必要性讲清楚。

## 验收记录格式

每章核对记录建议写入：

```text
paper/reviews/section_review_章节文件名.md
```

记录内容建议包含：

```markdown
# 章节验收记录：章节名

## 章节文件

`paper/sections/xx_xxx.md`

## 来源追溯

| 论文内容 | 来源文件 | 说明 |
|---|---|---|
| 结论或公式 | `docs/...` | 来源依据 |

## 自检结果

- 结构完整性：
- 结果可追溯性：
- 图表引用：
- 符号一致性：
- 与前文重复：

## 需要用户确认

1. ...
```

## 进入下一章条件

只有满足以下条件，AI 才能进入下一章：

- 本章 `.md` 已生成。
- 本章验收记录已生成。
- AI 已向用户说明本章主要内容和待确认点。
- 用户明确确认、或给出修改意见并完成修改。
